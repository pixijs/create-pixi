Choosing a template

Every template is a working PixiJS project. They differ in build tool, in how much code they start you with, and in what you're building.

If you're making a game, start with a game template: pick the platform it runs on, and whether it's multiplayer. It's the Vite template plus the libraries most games add, and you can remove the ones you don't need. For anything else, or if you're unsure, start with Vite. Its config only sets base: "./", the dev server port and open: true. The game and React templates use Vite too, so you can move to them later without learning a new build tool.

What every app template includes​

All templates except the extension template share these:

  • A public/ folder for static files such as images and the favicon.
  • A dev server on port 8080. See change the dev server port.
  • oxlint and oxfmt with lint and format scripts, plus VS Code settings that use the Oxc extension to lint and format on save.
  • A .gitignore for node_modules, dist and editor files.
  • PixiJS 3D, with a spinning cube that shows 3D and 2D on one stage.

The extension template uses PixiJS Extension Scripts for building, linting and testing instead, and lists PixiJS 3D as a peer dependency.

TypeScript or JavaScript​

The table above shows which languages each template comes in. When a template has both, pick JavaScript at the language prompt or use its -js id. TypeScript and JavaScript explains how the two versions differ.
